## 可追溯的 Ruff 失败与回归

1. **失败。** 在 `ruff-conditions/unknown` 的 A 中，原生 DRA 成功绑定并交付，原报告的第一条 finding 额外断言 `scripts/check.py` 自动使用仓库根配置。该回执的原 run ID 为 `run_5472e8510cd0465380584e6991d4870a`。索引保留原候选、原交付哈希、引文和复核后的盲评输入哈希。 [冻结题面](fixtures/ruff-unknown.json) · [原运行证据索引](corpus.json)
2. **定位。** 题面只确认根目录与 `services/` 的配置。根目录和 `services/` 之外，`scripts/` 可以有或没有更近配置。两种布局均满足题面，按同一固定规则读取时会选不同文件。这个前提已显示在生成器可见的原题条件里，生成却把不完整的目录信息当成了完整清单。引文精确绑定成功之后，仍需单独判断结论是否有据。 [Ruff 0.14.6 固定规则](https://github.com/astral-sh/ruff/blob/59c6cb521d26380120f8522476fd09d296bf4f2e/docs/configuration.md#L255-L282)
3. **修正与回归。** C 在首轮补上“没有更近配置”的条件。三次新增复跑里，A 两次再现无据断言，C 两次给条件、一次省略可选推断，三次均答全必答点。独立语义复核也确认复跑第三对中有一条独立的引文不足，改判该条不影响配对结果。 [复跑配对证据](corpus.json)
4. **正常对照。** 已知没有更近配置时，两版都直接给根配置。已知有 `scripts/ruff.toml` 时，两版都直接给更近配置。显式 `--config` 仍使两个文件都采用根配置。 [根配置对照](fixtures/ruff-root.json) · [更近配置对照](fixtures/ruff-override.json)

## 资源、复跑和遗留项

本次新增生成由八个独立的 Codex `gpt-6.2-sol` 上下文完成，每版各四次。Codex `gpt-6.2-astra` 在独立上下文做全量语义盲评和覆盖盲评。Go 对照的独立复核另用一个 Astra 上下文。DRA 在本地接收候选、精确绑定冻结引文、持久化并读回。外部模型 API 调用为 0，人工校准分母为 0。可比的生成纯耗时、模型 token 和每次生成费用未观测，保留为未知。旧脚本模拟资源值只适用于脚本路径。

在已有 Python 3.11 和仓库 [依赖锁](../../../constraints.txt) 的环境，从仓库根目录执行：

```sh
PYTHON_DOTENV_DISABLED=1 LANGSMITH_TRACING=false LANGCHAIN_TRACING_V2=false \
  python benchmarks/findings-quality-v1/scoped-inference/replay.py \
  --output-dir output/scoped-inference-replay
```

回放重新生成原生协调器输入并比对哈希，把留存候选交给应用绑定器，检查持久化回读和盲评输入哈希，再用冻结的评审结果计算配对。每次回放产生新的 run ID，输出同时记录原始 run ID。再次运行时使用新的输出目录。原始会话、完整运行回执和临时输入保存在本地忽略目录。回放命令复核绑定和评分，新增模型采样需另外运行受控实验。
