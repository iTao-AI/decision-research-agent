# Decision Research Agent v0.1.8

Release preparation date: 2026-07-30.

## Supported Surface

v0.1.8 prepares a provider-free local runtime closure for custom MySQL reads,
dependency verification, and privacy-safe failure delivery. The application
database remains the business authority; LangGraph checkpoints remain
execution-position state; observation and optional tracing remain diagnostic.

Required verification is local and provider-free. This tracked preparation
record does not itself claim publication, deployment, provider-backed
execution, or business acceptance.

## Changes

- Compose separates MySQL server, one-shot principal bootstrap, and backend
  credential authority. Backend startup attests `CURRENT_USER()` and exact
  SELECT-only grants before creating its connection pool.
- A bounded one-statement scanner accepts only SELECT/CTE input and rejects
  comments, additional statements, and dangerous read-side constructs before
  connection acquisition.
- Custom queries return at most 100 rows, fetch in batches of 25, serialize no
  more than 65,536 bytes, and use a default 5,000 ms server statement limit.
- Connector/Python pooled wrappers are returned through their public
  `close()` contract on success, error, timeout, and cancellation paths.
- Runtime exceptions cross logger, model/tool, monitor, telemetry, artifact,
  REST, WebSocket, harness, and task-callback boundaries only through closed
  stable codes and fixed messages.
- `greenlet==3.5.4` closes the SQLAlchemy 2.0.51 transitive runtime lock. The
  dependency checker accepts a clean `pip check` or exactly the approved
  `ragflow-sdk 0.13.0` / `pytest==9.0.3` metadata diagnostic and rejects every
  additional or near-match diagnostic.

## Compatibility And Migration

Operators using external MySQL must provision the configured application
principal with exact SELECT-only access to the configured schema. Startup
fails closed when `CURRENT_USER()` or `SHOW GRANTS` differs from that contract.

For Compose, set distinct non-empty `MYSQL_ROOT_PASSWORD` and
`MYSQL_PASSWORD` values. The `mysql-bootstrap` one-shot service reconciles the
application user by dropping and recreating it on every startup, including an
existing Compose volume. This removes direct grants, grant options, granted
roles, and default roles before applying exact SELECT-only access and allowing
backend readiness.

`MYSQL_QUERY_TIMEOUT_MS` defaults to `5000`; accepted values are `100` through
`30000`. Query consumers must accept stable row/byte truncation metadata and
must not depend on unbounded custom-query output or raw exception strings.

v0.1.7 remains immutable and is affected by the corrected boundaries described
here; its tag, release note, and historical claims are not rewritten.

## Rollback

Stop recommending v0.1.8 and restore one previously approved source, exact
dependency lock, and runtime configuration tuple. Stop writers before changing
application revisions and verify the restored tuple with its own release
gates.

Do not move published tags, weaken database grants, or bypass startup
attestation as a rollback shortcut. Preserve the current database and obtain
explicit authority before any data restoration.

## Required Verification

The exact release candidate requires the dependency/import checks,
deterministic proof gates, full provider-free and required Docker test lanes,
frontend tests/lint/build/audit, canonical identity and presentation audit,
real `SHOW GRANTS`, schema/data identity, pool reuse, timeout/truncation, and
task-owned zero-residue cleanup specified by the tracked v0.1.8 implementation
plan.

No required command calls a paid provider or remote tracing service.

## Known Limits

- This preparation record does not claim that v0.1.8 is published, tagged, or
  available as a GitHub Release.
- No deployment, live-provider result, hosted production, multi-tenant
  authority, SLA, or business impact is claimed.
- The scanner is a deliberately narrow SELECT/CTE contract, not a general SQL
  parser or a database-layer rewrite.
- Exact SELECT-only grants reduce application authority; they do not replace
  transport security, caller authentication, per-user authorization, RBAC, or
  operator-owned backup and recovery controls.
