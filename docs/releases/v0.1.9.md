# Decision Research Agent v0.1.9

Release preparation date: 2026-09-01.

## Supported Surface

v0.1.9 records current default-branch additions after the immutable stable
`v0.1.8`: frontend lock maintenance, the deterministic native Console
showcase, maintained Node.js 22/24 support, bounded failure diagnosis, one
bounded Live Backend research question, and GET-only reattachment of a known
run. The backend, API, application-owned ResearchRun and EvidenceLedger,
review, verification, publication, and canonical-result boundaries remain the
same.

The application database remains business authority. The Console is a consumer
of service-owned state and does not own human review, verification, publication,
or delivery authority. Human review and release authority remain outside the
Console. Failed sources remain immutable and not delivered.
Blocked failure states remain `review_required` and `not_delivered` for the
failed source.
The Static Demo capture fingerprint canonicalizes only release `version` fields
in the frontend package metadata, so this identity-only release bump does not
re-capture the PNGs; dependency, build configuration, source, and public-asset
changes still require a new fingerprint and provenance.
Verification for this release preparation is provider-free, local-only, and
non-production; no business-impact or adoption claim is made.

## Changes

- Refreshed frontend transitive security locks without changing dependency
  choices or runtime behavior.
- Added native deterministic Static Demo showcase frames with squash-portable
  provenance contracts.
- Modernized and retained the frontend Node.js 22/24 support matrix in package
  metadata and CI.
- Replaced frontend test patches and refreshed showcase provenance/assets.
- Clarified bounded blocked-failure diagnosis while preserving
  `review_required` and `not_delivered` for the failed source.
- Added one bounded user-authored generic research question to Live Backend,
  limited to a nonblank value of at most 4096 UTF-8 bytes. The exact submitted
  bytes remain bound to same-key, byte-equivalent ambiguous-create replay.
- Added health-gated GET-only reattachment for a retained known `run_id` after a
  page refresh. It does not add run history/listing, browser persistence, or
  ambiguous POST replay.

## Compatibility And Migration

No runtime API, schema, domain, or authority migration is required. Existing
backend and Console paths continue to use the same service-owned status,
canonical result, review, Evidence, and delivery contracts.

The Live Backend question is browser-session-only and is not normalized,
translated, rewritten, or promoted into business authority. An ambiguous
create may be reconciled only with the same key and byte-equivalent request.
Known-run reattachment is GET-only and observes the retained service-owned run;
it does not reconstruct an ambiguous POST after refresh. The v0.1.8 tag,
release note, and historical claims remain immutable; v0.1.8 remains immutable
as a stable historical release.
