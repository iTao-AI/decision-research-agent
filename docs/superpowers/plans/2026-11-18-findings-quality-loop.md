# Findings quality loop implementation plan

> Implement the [approved design](../specs/2026-11-18-findings-quality-loop.md) with `superpowers:executing-plans`. The delivery owner manages the work, reviews changes, resolves defects and accepts the local result. Return material changes to the goal, design or acceptance standard to the design owner.

**Goal.** Starting with a delivered research report, capture a suspect finding, judge it against the citations it actually used, and reproduce a paired comparison on a local machine.

**Architecture.** Place the evaluation beside the existing benchmark scripts. Read validated deliveries, keep inference inputs separate from labels, and derive the readable report from one versioned JSON result. All new observations are local to the evaluation. Reuse existing contracts, the native candidate writer and frozen-ledger validation.

**Stack.** Repository Python 3.11, its locked dependencies, pytest and the current DeepAgents/LangGraph harness where native generation is exercised. Base `b0d3fdb1bb37d0e7f74dd1687c6421617ba29f5f`. The examples below assume invocation from the worktree root.

## Constraints and review focus

- Independent dimensions include origin, label status, execution outcome and semantic verdict. Infrastructure failures, filtered records, missing review and unsupported source binding must remain visible in their own counts. Use null for unobserved cost or usage. A replay cannot mint new model observations.
- Score the full accepted question scope. One valid quote cannot compensate for an unrelated or contradicted conclusion, an unanswered answerable question, or a newly invented material claim.
- Blind inputs exclude labels, expected results, fixture category names, scripted answers and scores. Group related sources before assigning splits. The public corpus must be portable and safe to redistribute. Historical artifacts do not become human labels or holdout results through import.
- Public routes, findings and Evidence schemas, delivery authority, telemetry v1 and production defaults retain their contracts. Local evaluation metadata may carry opaque run/segment/call identities and allowlisted phase/counts. Real provider execution and external publication are separate from local verification.

## Task 2 — Independent scoring and a local results table

**Inputs and outputs.** Add `replay` to the same CLI. Consume the frozen manifest and retained generation/Judge/manual records. Write `report.json` and its deterministic projection `report.md` in an explicit output directory. Use stable ordering, portable relative evidence links and separate comparable versus planned denominators.

- [ ] Write failing tests with one correct paraphrase, one fully bound but contradicted statement, one insufficient-condition claim and a pair of conflicting sources. Assert that a missing excerpt yields a structural error, a failed Judge yields an unscored result, and an absent report differs from a task that never ran.
- [ ] Make the Judge return verdict, matched reference IDs and a short rationale; reject invented IDs and invalid outputs. Give each Judge only the same question, statement and actual cited material. Provide a recorded-Judge replay that requires no network. Bind receipts to input hash, rubric revision and model identity; keep the generator and Judge configurations separate. Produce calibration statistics only from independently human-reviewed rows. Show reviewed counts, four-class confusion, false positives, false negatives and uncovered categories. Synthetic expected outputs test the accounting even when no human sheet has been returned.
- [ ] Predeclare required answerable points, required unresolved points and forbidden overclaims for each task. Report supported coverage and wrong refusals as well as findings-level scores. For comparable A/B rows emit both-pass, A-only, B-only and neither-pass plus per-question changes. Show planned, started, delivered, comparable and unscored counts; a zero denominator gives no statistic. Keep generation cost and evaluator cost distinct.
- [ ] Render a compact Markdown table. Each row leads to the relevant run, case, original claim, cited excerpt and verdict; include earliest known deviation, newly introduced claims, resource observations and final decision. No browser or hosted platform is needed to inspect a fixed experiment.
- [ ] Test stable output with shuffled input ordering, all-abstain, A correct/B wrong, an unstarted row, missing usage and pending manual review. Use two fresh output directories, run the following twice, and compare both files byte-for-byte. For CI use temporary outputs, network disabled, and no dotenv or API keys. Commit the runnable offline report and its targeted checks.

PYTHON_DOTENV_DISABLED=1 LANGSMITH_TRACING=false LANGCHAIN_TRACING_V2=false \
  python scripts/findings_quality.py replay --dataset benchmarks/findings-quality-v1 --output-dir OUTPUT
