# 决策研究助手首页与常驻任务栏

普通入口 `/` 打开一间可以马上开始工作的研究台。第一次来的用户应当能在首屏看懂这个工具产出什么，找到提问入口，也知道提交后在哪里看进展。运行期间保留整个首页。只有使用者主动打开报告、原因、证据或设置时，才展开对应内容。[打开可交互的首页设计稿](../../assets/research-workspace/decision-research-home-v2.html)

## 这次纠正的体验

在 `2ad0d70` 的浏览器页面上，首页主体是一张提问表单，客服退款示例出现在提问区。提交时 URL 保持不变，但 `ResearchWorkspace.tsx` 由 `showDraft` 控制整块正文切换，`focusOnRun` 又把焦点和滚动位置移向新标题。用户看到的是一次跳页。这次修订替代了[首版设计](2026-11-20-research-workspace.md)中「正文自动切换」和「首页放示例」两项决定，保留独立编号查询、既有报告读法与来源返回路径。

## 一屏能看到的内容

| 位置 | 页面内容 | 为什么放在这里 |
| --- | --- | --- |
| 页眉 | DRA 决策研究助手、查找研究、服务连接。连接入口同时提供服务地址、修改及重连。 | 已有运行的编号只在查找时填写。连接问题有自己的入口。 |
| 页眉下、全宽吸顶 | 一枚形状可辨的图标、状态名、当前研究的短标题，以及该阶段的一项动作。滚动时保留这条栏。 | 目光停在同一位置就能认出准备、运行、交付和失败。标题过长时截断，详情显示全文。 |
| 首屏左 | 「把公开资料整理成有出处的研究报告。」用一句话说明可回看原文、追问未解问题。简短的来源与结论图示只解释这两者的关系。 | 提交之前就知道会拿到什么。首页没有历史案例、样例问题、示例报告或发布元数据。旧案例可沿现有明确的展示链接访问。 |
| 首屏右 | 空白的研究问题、添加子问题、现有研究模式和紧邻的「开始研究」。不可提交时就近说明原因。 | 不需要先点介绍、填运行编号或翻屏。系统接收后原问题仍留在此处。 |
| 首屏下部 | 三个可以进入的模块，分别说明比较、核验和续研。桌面三列，窄屏纵向排列。 | 用户按自己的目的进入详情。每个模块都有具体操作。 |

视觉采用暖白纸色、深墨青主面板、偏衬线的中文标题和清晰的无衬线操作文字。让标题、提问区与功能模块形成三个能辨识的层级。模块用窄色线和淡底区分，当前任务的颜色集中在顶栏。小屏将产品说明缩为两行标题加短段，移除纯辅助图示，保留问题框和提交按钮。按照现有中文、英文切换适配文字换行。

## 顶部任务栏

| 条件与事实来源 | 可见反馈 | 主动作 |
| --- | --- | --- |
| 没有当前任务 | 灰绿空心符号「当前无任务」。服务连通状态另见页眉。离线时仍可写草稿，注明提交所需条件。 | 无 |
| 浏览器正在创建 / 服务已接受 / 服务明确返回 pending | 琥珀色钟面，分别写「正在提交」「已接收」「等待执行」。三者同属准备阶段。 | 查看进展 |
| 当前运行返回 running | 蓝色转环或活动点「运行中」及原问题。只列已观察到的事件。 | 查看进展 |
| 服务允许交付，正在读取 | 蓝色「正在读取报告」。进入 result 且结构化 findings 或通用结果已读回并通过现有校验，才显示绿色勾「报告已就绪」。 | 就绪后「阅读报告」 |
| 执行状态明确为 failed | 朱红叉「研究失败」。能定位原因时加「执行超时」等短语，长说明放入详情。 | 查看原因 |
| 等待复核 / 交付受阻 / 等待交付 | 琥珀色提示符加原始语义。交付门禁与执行结果分开呈现。 | 查看交付说明 |
| 状态或报告读取中断 | 琥珀提示符「状态读取中断」或「报告读取中断」。保留已知任务与观察。 | 恢复查看／重读报告，按同一个编号 GET |
| 创建回执不明 / 被明确拒绝 | 分别显示「提交回执待确认」或「提交未成功」，保留冻结请求或可编辑草稿。 | 核对同一请求／编辑问题，沿用原有幂等规则 |

上色同时采用文字与不同图形。动态提示只在运行期间出现，开启减少动态效果后用静态图标表达相同状态。辅助技术只在阶段变化时播报，不随着轮询、计时或动画重复播报。不估算百分比、完成时间或当前搜索步骤。终态持续可见，直到用户明确开始另一项研究。打开已有研究时，保留当前提交的任务身份，查阅对象显示自己的标题和状态，不能覆盖正在观察的任务。

## 首页在运行时怎么用

- 整个生命周期都保留介绍、提问区和三个模块的 DOM 与顺序。点击提交后留在原 URL、原滚动位置和原操作上下文。按钮保留为可聚焦的原控件，冻结此次输入并阻止重复提交。进入终态可主动新建研究。异步结果到达时，已打开的模块、键盘焦点与正在看的位置都保留。
- **多问题比较**进入问题编排，证据研究支持合计 1–5 个明确问题，沿用顺序、长度校验和问题标识。通用模式继续支持单问题。已提交的问题可以查看，编辑或新建需要用户主动操作。
- **核对结论出处**在有可读证据报告时进入其问题与引用。选择引文能打开对应原文或服务端保留的片段，再返回同一引文。没有可读报告时显示使用方式，并直接提供「查找已有研究」。通用报告按实际返回内容呈现。
- **跟进未解问题**从本次真实报告的待查项生成可编辑的新研究草稿，明确提交后才产生新运行。若全部已解、报告只支持通用阅读或尚未有报告，就说明当前情况，保留查找已有研究的入口。
- **阅读报告**或**查看原因**只在用户点击时展开。桌面可以打开正文或侧栏，小屏用单列详情并提供可见的返回操作。返回恢复原触发控件和滚动位置。看报告或来源时仍能辨认顶部任务状态。失败详情依次呈现已知停止阶段、原因、实际保留的内容及可做的事。来源链接、留存片段和缺失信息的措辞均以投影字段为准。

## 验收情景

1. 新用户在 1280 × 720 和 390 × 844 打开普通中文首页。首屏能读到用途、看见输入和提交。三个模块在页面上可见或可以顺序滚到。首页无示例内容。英文、键盘导航、减少动效模式可用。
2. 提交一个有效问题。记录地址、首页表单节点、问题值、焦点及滚动位置。从准备到运行再到成功，这些持续稳定，提交只发生一次。背景状态变动不会关闭已打开的模块或抢走焦点。实际结果成功读回时，顶栏持续给出「阅读报告」。主动打开、看一处证据、返回到原触发位置。
3. 分别走一条真实前端配可控后端夹具的执行失败路径和一条观测断开路径。前者顶栏持久显示红叉及停止原因入口，后者显示可恢复读取的提示。恢复读取沿用原运行编号，产生零次新建请求。首次加载地址不可用时，能从页眉修正地址并保留草稿。
4. 有、无现成研究时分别打开三个模块。验证 1–5 问编排、按编号 GET、已绑定与缺失的引文、无待查项和有待查项的续研行为。浏览另一项已有研究或来源时，当前任务不会被替换。
5. 在真实浏览器保留桌面和窄屏首屏、运行、就绪、失败的可核查画面。区分离线设计稿、本地运行夹具与真实研究产生的结果。沿用工程既有测试以及本次覆盖的渲染和交互回归。

离线交互稿支持填写并原地提交、打开模块、体验子问题编排及查看不同的任务颜色。页尾「交互稿 · 状态预演」只用于手动触发界面状态。正式应用从现有运行观察和报告读取逻辑驱动。前端交付沿用已有接口、证据数据、提交幂等和续研契约。
