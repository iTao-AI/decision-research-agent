# DRA 研究工作台改版设计

普通首页打开一份空白研究草稿。用户在首屏写问题、提交，在同一位置看进展，交付后直接阅读报告并核对引文。沿用现有真实后端、静态案例和读取契约。首个实施版本应让这条路径完整可用。[打开四态交互线框](../../assets/research-workspace/2026-11-20-research-workspace.html)

## 首轮裁决

1. **首屏给提问。** 普通入口 `/` 默认为真实研究工作台。原来的合成案例从页首「示例报告」独立打开，保留 `/?showcase=overview|evidence|blocked` 的明确入口及离线能力。新草稿为空，示例文字要用户主动填入才能成为问题。
2. **一处持续显示任务状态。** 全局顶栏下放一条吸顶状态栏。左侧用一句话说明连接或当前研究状态，右侧只放这个状态下有用的动作。滚动长报告、查看证据、展开诊断时仍能找到它。首屏无需学习工作流步骤或技术名词。
3. **报告就在研究页内。** 服务端允许交付且客户端已成功读回时，正文在主区域直接出现。「阅读报告」定位并聚焦正文。点击结论旁的来源编号可查看对应摘录和留存片段，再返回该处继续阅读。

2026-11-20，在主线 `d11e3a3` 的本机控制台做了浏览器走查。普通首页首先展示合成报告。展开「Live 状态」、选真实后端并成功检查连接后，在 1280 × 720 视窗内，提问框顶部距文档顶约 2113 px，提交按钮顶部约 2410 px，页面可见文本中出现 15 次「尚未观察到」。这是默认通用模式、尚未提交任务时的一次测量。线框在同尺寸下把空问题框顶部放在约 323 px、提交按钮底部放在约 458 px。验收关注无需滚动即可操作，不绑定这些精确像素。

## 页面结构与入口

| 区域 | 设计与行为 |
| --- | --- |
| 顶栏 | 左侧 DRA 品牌，右侧「查看已有研究」「示例报告」「设置」。语言和本地地址在设置中。「查看已有研究」单独展示运行编号输入、格式错误及打开动作。它的校验只影响自己；打开再取消保留草稿、当前观察和焦点。已知编号仅走健康检查与 GET，活跃研究可用独立阅读上下文。 |
| 状态栏 | 新研究时显示连接状态，已有研究时优先显示当前任务。一次用户动作只需一处主要状态反馈。设置、旧运行查询和诊断有明确返回路径；阅读当前研究时保留其上下文。 |
| 提问主区 | 一个常显标签、空白多行输入、与它同组的「开始研究」。底部可添加子问题和选择研究模式，附近解释空白、超长、离线或正在提交等禁用原因。提供一个可选的填入示例，不自动提交、不覆盖用户文字。 |
| 运行、报告及依据 | 主区随阶段切换。运行中仅列已观察到的事件；完成后以问题为标题、按服务端接受的顺序组织内容。选择引文才出现旁侧来源栏；窄屏在当前阅读流展开并提供「返回引用处」。 |
| 诊断与高级信息 | 执行状态、运行编号与复制操作、门控、错误码、artifact 等按需展开。运行期间能取回编号以便断线接回。架构和 CLI 说明放到二级入口。 |

**两个有意调整的界面默认值。** 普通首页直接呈现提问工作台；新建表单默认选择可见且可切换的「证据研究」，提交时显式传 `generic-evidence-report`，让第一份报告就具备逐题引用阅读的机会。「通用研究」继续可选，CLI、服务端及未传 profile 的调用保持原语义。明确的 showcase 路由仍加载原合成案例且不联系后端。真实工作台仅对已允许的本地端点自动做一次只读健康检查，连接失败时保留输入，并提供重新连接和设置。更改端点按现有校验和请求失效规则处理；从未手动提交的页面产生零次创建。

## 四种主要状态

| 状态 | 用户看到什么 | 当前可做什么 |
| --- | --- | --- |
| 未开始 | 「本地服务已连接　请输入研究问题」、标题和输入框。连接检查中、失败分别有准确提示。空表单就近提示「输入研究问题后即可开始」。 | 输入后点「开始研究」。结构化研究可编辑 1–5 道题，保留稳定 question ID 和既有字数、字节上限。切换模式明确处理已有草稿。 |
| 运行中 | 保留题目。客户端正在提交可写「正在提交」；有创建回执可写「请求已接收」；服务端 `pending/running` 分别写「等待执行／研究运行中」。只有收到记录才列事件。 | 看进展、查看详情、取回编号。正常轮询显示「无需操作，页面会自动更新」。没有观测到检索、分析、撰写时，不显示这些步骤、百分比或预计剩余时间。 |
| 已完成 | 观察到服务端 `completed` 或 `completed_with_fallback`、交付为 `ready`，且相应读取成功后显示「报告已就绪」。等待或读回失败采用独立状态。 | 阅读正文、从结论查来源、查看完整片段、下载原始 UTF-8 Markdown，或新建研究。原生 Markdown 与结构化报告按观察到的实际 profile 分流；合成或生成的文字不用作缺失字段的默认内容。 |
| 失败 | 给出停止阶段、已知原因、实际保留的资料或已知数量、报告可用性。线框用服务端已返回 `execution/run_timeout` 且留有一条资料的模拟样本。未给出原因时说「服务端未提供停止原因」。 | 查看已有资料与诊断；有原题时可「编辑问题，另开研究」，仅填回草稿，再次主动提交才创建新的 run。无原题时提供空草稿。 |

**容易混淆的状态另作处理。** 浏览器获取回执不确定，保留冻结请求和同一幂等键，提供「重试同一请求」或放弃待确认请求。已知 run 但轮询/读取中断时提供「恢复查看」，仅 GET，不能写成研究执行失败。执行结束且 `review_required` 或 `blocked` 时分别解释待复核或交付被阻止；有对应观测才展示诊断、已保留资料和下一步。「查看状态」读取已有研究，不增加审批写入。已完成但仍有未决子问题时，保留原有勾选、编辑和显式创建独立续研的能力。[创建与恢复](../../demo-console.md#run-data-and-recovery-contract) · [API 与交付门槛](../../reference/api-contract.md)

## 视觉、中文与无障碍

沿用 DRA 品牌，把空间让给可读的提问与报告。主画布用浅灰绿 `#F5F6F2`，正文为墨色 `#1E302C`，主操作为松绿色 `#18584A`。错误只在对应的局部区域使用暗红。大号中文衬线用于题目与报告标题，操作、状态、正文用现有系统无衬线，技术编号在详情中用等宽字。文档式纵向节奏、细分隔线和一张主操作表单替代早期的多列控制面板。不新增字体下载依赖。

桌面提问列上限约 800 px，报告约 940 px；展开来源时让正文和来源并列。窄屏保留提问、提交和查旧研究，来源接入单列阅读。选中的模式和语言以选中语义、文字与可见样式表明；不可执行的动作才用禁用态。状态变化用可访问的状态区域轻量播报，相同轮询结果不重复播报。弹层支持键盘、Escape 与焦点返回。引文、问题目录与锚点为吸顶区域预留滚动偏移。

## 给实施窗口的验收

- **首屏。** 1280 × 720 与 390 × 844 两种视窗，从普通首页开始，输入框和提交按钮均完整可见且无需滚动。对照真实浏览器几何与截图，检查空草稿、填入、离线、焦点及窄屏横向溢出。已有研究的 ID 在独立入口；检查中或后端离线仍可起草，未提交时没有报告错误或空门控卡。
- **黄金路径。** 在受控本地后端，从真实网页输入两道题、提交一次、观察真实服务状态并打开可读报告。从结论追到绑定的摘录、展开留存片段、返回原处；下载内容与本次 canonical Markdown 字节一致。另检查通用模式、自选既有 run 和无后端的明确 showcase 页面。
- **失败与恢复。** 独立覆盖有原因/原因未知的失败、待复核/阻止交付、创建回执不明、轮询中断与报告读取失败。核对每个状态的动作、POST 次数和 run 身份。前端切屏或重复点击不能复制请求；报告、引用、已保存状态及恢复动作均从已有服务观测导出。
- **复用与交付。** 优先调整 App 的层次、视觉、文案和 UI 状态映射。复用现有 live 流程、校验、证据及结果阅读器、续研草稿、安全链接与下载处理。同步更新 `DESIGN.md`、控制台文档、双语描述和受影响测试。用项目自身的前端检查与真实浏览器复核桌面/窄屏四种状态，注明是真实运行还是 fixture。网页验收针对交互与状态，受控后端足以证明 UI；正文事实是否正确由原有评测负责。

独立 HTML 是可离线阅读的设计样稿。底部四态切换、演示编号及模拟接收的数据只用于审稿。最终 UI 接入现有真实状态和正式读回数据。
